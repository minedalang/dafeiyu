# 小鲸鱼生命系统 · 机制与数据记录

本文件用于说明**代码中的真实规则**，不是模型生成的故事设定。所有时间按照运行电脑的**本地时间**。关机期间程序不运行；下次启动从持久化记录中补算，不会调用大模型。

## 1. 关机/离线场景对照表

| 电脑及宠物状态 | 下次启动时的生命状态处理 |
| --- | --- |
| 23:00 关机，次日 08:00 开机 | 22:00～次日 07:00 中重叠的 **23:00～07:00 共 8 小时**算作睡眠；07:00～08:00 按醒着时的被动变化结算 |
| 19:00 关机，次日 08:00 开机 | 19:00～22:00 和 07:00～08:00 按醒着结算；**22:00～07:00 共 9 小时**算作睡眠 |
| 14:00 正在执行午睡活动时关机 | 根据保存的 `sleep_until_at` 只计算剩余计划中的睡眠时间，到期后按醒着结算 |
| 白天关机，夜间前重新开机 | 不自动按长时间睡眠结算（除非关机前正处于有效午睡） |
| 关机几天 | **只计算距离开机最近的 24 小时**，更早的时间计入审计裁剪时长，不产生无限收益 |
| 关闭再立即打开程序 | 已补算的时间写回 `updated_at`，不会再次结算同一区间 |
| 同一时段既在夜间时窗又属于午睡计划 | 只计算**一次**睡眠，不会重复恢复 |
| 夜间主动叫醒后关机 | 叫醒的即时状态变化保留；晚上 22:00～07:00 可再次按自然夜间睡眠补算 |

离线与在线现在共用夜间 22:00～07:00 的作息边界：夜间在线入睡后计划可一直持续到 07:00（最长 9 小时）；离线则在下次启动时按同一段夜间时窗补算。关机只在重启时结算，关机期间**没有**播放动画或 API 请求。

## 2. 状态变化速率（每分钟）

数值限制为 0～100；同一个分钟只结算一种活动。正号为上升，负号为下降。

| 活动 | 精力 | 饥饿 | 困意 | 心情 |
| --- | ---: | ---: | ---: | ---: |
| 醒着闲置（白天） | -0.055 | +0.075 | +0.048 | 逐渐回归 68 |
| 醒着闲置（22:00～07:00） | -0.055 | +0.075 | +0.14 | 逐渐回归 68 |
| 睡眠（`nap`） | **+0.53** | +0.045 | **-0.90** | +0.055，另有回归项 |
| 工作（`work`） | -0.16 | +0.09 | 白天 +0.09、夜间 +0.15 | -0.016 |
| 游戏、音乐、玩耍、模仿 | -0.065 | +0.085 | 按默认白天/夜间速率 | +0.12 |
| 运动（`sports`） | -0.24 | +0.12 | +0.095 | +0.16 |
| 放松（`rest`） | +0.13 | 按默认速率 | -0.075 | +0.085 |

**额外一次性变化：** 每种早餐、午餐、晚餐一天仅第一次执行时饥饿 -38、精力 +7、心情 +5；用户主动聊天心情 +1.5；被叫醒会增加困意（夜间 +9、白天 +4），并降低心情。多次播放同一段动画不会重复领取一次性奖励。

## 3. 持久化与核对数据

主数据文件为应用数据目录下的 `whale-life-state.json`：

| JSON 字段 | 作用 |
| --- | --- |
| `updated_at` | 已结算至何时（Unix 时间戳），再次开机不会重复计算 |
| `needs` | 当前精力、饥饿、困意、心情（0～100） |
| `sleep_until_at` | 已接受午睡计划的结束时间；关机后只补它尚未结束的部分 |
| `meals` | 同一天用餐去重 |
| `events` | 最近最多 12 条生活事件摘要 |
| `offline_settlements` | **最近最多 24 次离线补算审计记录**，包括即使没睡的白天离线场景 |

`offline_settlements` 每条记录有：`started_at`（离线开始）、`settled_from_at`（24 小时窗口实际补算起点）、`finished_at`（结束）、`sleep_minutes`（合计睡眠分钟）、`night_sleep_minutes`、`daytime_nap_minutes`、`discarded_minutes`（超出窗口的时间）、`before` 和 `after`（四项数值）。这些时间戳可用本地时区转换显示。

> 这里没有持久保存屏幕截图、聊天原文或 API Key。审计只反映模拟结算，不是对现实睡眠的医学或行为检测。

## 4. 拖动睡觉中的小鲸鱼

正常拖动只调整桌面坐标，**不会取消睡眠计划，也不应切换悬空/待机动画**。双击叫醒仍可按原交互触发；刻意快速甩出属于抛掷物理交互，可能被解释为真正打断。

## 5. 排查清单

如果早上困意还很高，依次查看 `whale-life-state.json` 的 `updated_at`、最后一条 `offline_settlements` 的 `night_sleep_minutes` 和 `before/after.sleepiness`。如果睡眠为 0，检查本地电脑时间和夜间时窗；如果时间很长但数值变化很小，检查状态是否已接近上下限或程序是否在关机前正确保存。必要时备份该 JSON 供排查，**不要发送包含私人对话的其他文件**。

## 6. 在线生命循环、数值与 AI 的关系

`WhaleLife.advance()` 是本地时间结算器。AI 自主服务启动后约每 **30 秒**调用一次，进入一次新活动、取消活动、用户聊天或被叫醒等关键事件也会即时更新或保存。**动画循环次数不等于重复结算次数**：播放三十遍同一段吃饭动画，不会让饥饿三十次减少 38 点。

| 生命值 | 数字越大表示 | 对模型的影响方式 |
| --- | --- | --- |
| `energy` 精力 | 更有精神 | 低精力时提供休息建议，但不会在代码中直接抢走控制权 |
| `hunger` 饥饿 | 越饿 | 高饥饿时提示模型考虑对应餐食，仍受当天用餐去重限制 |
| `sleepiness` 困意 | 越困 | 高困意时提示休息或睡觉；睡眠分钟逐渐降低困意 |
| `mood` 心情 | 越开心 | 低心情时建议放松或娱乐；聊天/玩耍可改善 |

`WhaleLife.snapshot()` 中的建议阈值目前大致是：困意 ≥70 优先真正睡眠；精力 ≤28 但困意未达阈值优先放松恢复体力，而不是强行睡觉；饥饿 ≥70 考虑用餐；心情 ≤37 考虑轻松活动。**这只是交给模型的 `goal` / `suggested_activities`，并不等于程序定时强制执行对应动画。**

按现有速率，睡前困意 84 且连续睡着、不发生其他活动时，理论上大约 94 分钟可把困意降到 0（84 ÷ 0.9 ≈ 93.3），之后仍受 0 下限约束。夜间睡眠 8 小时后困意仍为 84 的情况，应该优先检查**真实计入的睡眠分钟**和启动时有没有发生离线结算，而不是直接认为“睡着了所以已恢复”。

## 7. 在线与离线睡眠不是同一个计时器

| 比较项 | 电脑开着，桌宠在线 | 电脑关机/程序退出后再启动 |
| --- | --- | --- |
| 时间来源 | 运行中的活动剩余时长 + 生命周期定时器 | 保存的 `updated_at` 到下次启动时的本地墙上时间 |
| 睡眠活动 | AI 选择 `nap`，白天 15～30 分钟；夜间最多持续到 07:00 | 22:00～07:00 直接按夜间时间段补算；已有白天午睡则只补剩余计划 |
| 是否每 90 秒问 AI | **不会** | 不会，关机时程序和模型都不运行 |
| 是否可以自动连续睡 6～9 小时 | **已支持夜间单次长睡** | 夜间时段内可以一次补算最多整段夜间睡眠 |
| 人工双击叫醒 | 可提前停止，并产生被叫醒的状态影响 | 关机期间无法点击；之后按既定时间窗口结算 |
| 状态保存 | 运行时定期及关键事件保存 | 启动补算后立即保存到同一个 JSON |

**现行行为：** Windows 从系统级睡眠恢复后，若在线计时器错过超过 60 分钟，`advance()` 会改用同一离线夜间分段算法补算，而不是把超出 60 分钟的时间直接丢弃。真实 Windows 休眠时序还需本机验证。

## 8. 审计字段示例与计算口径

以下是**示意结构，不是你电脑上真实产生的一条记录**。生产数据由 `pet/life_state.py:reconcile_offline()` 生成：

```json
{
  "started_at": 1761001200.0,
  "settled_from_at": 1761001200.0,
  "finished_at": 1761048000.0,
  "sleep_minutes": 540.0,
  "night_sleep_minutes": 540.0,
  "daytime_nap_minutes": 0.0,
  "discarded_minutes": 0.0,
  "before": {
    "energy": 35.0,
    "hunger": 25.0,
    "sleepiness": 84.0,
    "mood": 70.0
  },
  "after": {
    "energy": 100.0,
    "hunger": 50.0,
    "sleepiness": 0.0,
    "mood": 80.0
  }
}
```

**请勿把示例里的时间戳和 `after` 数字用作校验基准**；准确数值须由实际时区、每段醒着/睡着的分钟数、初始数值、上下限和心情回归项共同决定。真正有用的是同一条记录中 `started_at`、`settled_from_at`、`finished_at`、三个睡眠分钟字段、`discarded_minutes`、`before` 和 `after` 的一致性。

补算逻辑对夜间时段与午睡计划取并集，不会在重叠区域双重计算；只取最近 24 小时，并把被裁剪的分钟数写入 `discarded_minutes`。每条补算记录都只落在本地状态文件里。`events` 保留最近 12 条摘要、`offline_settlements` 保留最近 24 条明细；正常聊天历史、截图、API 密钥不在这份审计文件中。

## 9. 修改规则时必须同步更新什么？

以后若变更夜间时间窗口、补算上限、午睡与夜间在线时长、每分钟变化率，必须同时更新本页的 **第 1 节场景表、第 2 节速率表、第 7 节线上/离线对照、第 8 节审计口径**；并更新 [机制速查表](MECHANISM-REFERENCE.md) 和 `pet/tests/test_whale_life.py` / `pet/tests/test_whale_sleep_drag_and_audit.py`。若只是修改人设或气泡文字，不应无意间改变生命值的结算逻辑。

## 精力与困意分离判断（2026-10-21 更新）

| 状态 | 精力 energy | 困意 sleepiness | 主要建议 |
|---|---:|---:|---|
| 体力耗尽但清醒 | 15 | 5 | `rest`（不自动要求睡觉） |
| 精力充足但困倦 | 95 | 85 | `nap`（睡眠需求高） |
| 又累又困 | 20 | 90 | `nap`（兼顾两种恢复） |
| 状态良好 | 90 | 10 | 根据本地时间与情境活动 |

- `fatigue_level` 是精力推导的 `exhausted`（≤28）/`tired`（≤45）/`ok`；`sleep_drive_level` 是困意推导的 `sleepy`（≥70）/`drowsy`（≥45）/`alert`。它们都是附加给 AI 的判断信息，不会擅自修改存档的四项原始生命值。
- 改变的只是 AI 提示和建议优先级，不改变每分钟生命值更新系数、睡眠时长上限、夜间作息与番茄钟。
- 如果饥饿 ≥70，在单纯低精力场景中优先建议进食，避免饿得没力气却一直睡觉。
