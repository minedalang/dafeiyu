# AI 自主决策：现行机制

> 对照：`pet/autonomy.py`、`pet/autonomy_intent.py`、`pet/activity_lifecycle.py`、`pet/app.py`、`pet/chat/ai_settings_page.py`。文档基线见 [索引](README.md)。

## 1. 基本流程

小鲸鱼的**动作由 AI 规划，本地程序执行**；模型不能生成新 WebM 动画，更不能通过自主动作 JSON 控制电脑。开启 AI 自主行为后：

1. Qt 主线程读取本地时间、桌宠位置/当前动画、鼠标、生命状态、近期活动，以及已有素材名单；只在获得授权时加入图片。
2. 后台线程经当前聊天 Provider 的 OpenAI 兼容 `chat/completions` 接口请求一份活动计划。
3. `parse_activity_plan()` 和 `parse_action_intent()` 拒绝超出白名单、缺少素材、非法 JSON 的内容；一次计划包含 **1～4 个步骤**。
4. 主线程根据计划播放已有动画、移动或显示文字气泡；持续活动由本地计时和循环负责，不是每次重播都调用模型。
5. `WhaleLife` 根据真实执行和经过时间更新数值，`AutonomyMonitor` 记录结果供设置面板读取。

正常请求不并发堆积；正在执行活动时的普通决策周期会跳过，避免抢占已有活动。关闭自主行为会停止自主计时并取消未完成计划；恢复原桌宠模式。

## 2. 启用及频率

| AI 设置项 | 当前默认 | 可用范围 / 说明 |
| --- | --- | --- |
| 让 AI 决定桌宠行为 | **关闭** | 开启后才产生正常 AI 自主决策和独立搭话 |
| AI 决策间隔 | **40 秒** | 20～300 秒；长期活动期间普通决策**跳过** |
| 允许自主识屏 | **关闭** | 独立隐私授权；不等于“开启自主行为就传屏幕” |
| 自主搭话最短～最长间隔 | **3～6 分钟** | 各 1～60 分钟；另一条独立计时链，见[搭话文档](AI-SPEECH-AND-PERSONA.md) |
| 生命周期本地更新 | **30 秒** | 不发起模型调用 |
| 持续睡眠检查 | **500 毫秒** | 本地检查循环是否仍在及是否到点，不发起模型调用 |
| 非睡眠长活动阶段评估 | **约 90 秒** | 满足可切换动画等条件才调用模型，不重置原计划时长 |

刚开启自主行为时可能在约 2.5 秒后发出首个非视觉决策。实际时间也受桌宠可用状态、正在处理的模型请求及系统调度影响。**上表是程序策略，不是 AI 自己设定的时钟**。

## 3. AI 可以建议的动作

| 动作 `verb` | 本地执行行为 |
| --- | --- |
| `idle` | 原有待机 |
| `walk` | 原有水平走路与边界约束 |
| `approach_cursor` / `retreat_cursor` | 靠近 / 远离鼠标 |
| `look_at_cursor` / `turn` | 看向鼠标 / 转身 |
| `play` | 必须指定当前素材确实存在的 `animation` |
| `say` | 气泡短句（最长 90 字） |

可选情绪仅包括 `neutral`、`happy`、`curious`、`sleepy`、`shy`、`excited`。未知动作、不能播放的素材或不合格字段会被拒绝；自主指令不具备文件读写、执行命令、网页或键鼠自动操作权限。

活动计划的结构示意：

```json
{
  "activity": "work",
  "duration_minutes": 8,
  "steps": [
    {"verb": "play", "animation": "写代码", "say": "先专心做点事。"}
  ]
}
```

这只是格式示例；**只有运行中的角色包确实包含「写代码」时才可执行**。`activity` 是语义分类，不是素材文件名；`free` 兼容不指定持续时长的自由动作。详细时长与动画过滤见[持续活动](ACTIVITIES-AND-ANIMATION.md)。

## 4. AI 看得到什么

- `local_time`：电脑本地日期、星期、推荐活动时段、睡眠倾向。
- `observation.life_state`：精力、饥饿、困意、心情、今天吃过的餐、近期生活事件及建议活动；建议不是强制阈值。
- `available_play_animations`：最多 128 个当前角色可用动画名称；不能凭空发明动作。
- `recent_actions` 和 `recent_activities`：各最多最近 8 条。
- `recent_dialogue`：最多最近 12 条用户/助手文本，每条最多 240 字；自主决策只读摘要，不等于永久完整记忆。
- 可选的 `user_message`、`ongoing_activity`、授权前台窗口观察/截图。

聊天时，在正常聊天 API 回复之外，自主系统**可能另外发一次**动作规划请求；两者共享角色语境但并非同一次调用。提示词由**动作 JSON 规则 + 人设设置**共同构成，详见[人设文档](AI-SPEECH-AND-PERSONA.md)。

## 5. 谁能打断谁

| 当前情况 | 新触发事件 | 结果 |
| --- | --- | --- |
| 普通自主决策已经完成，进入持续工作 | 下一次 40 秒周期 | 跳过，不抢占工作 |
| 非睡眠多动画长活动 | 约 90 秒阶段更新 | 可更换下一个动作，**不能换活动 / 延长结束时间** |
| 持续睡眠 | 90 秒阶段更新 | **不会进行** |
| 当前持续活动 | 单击 | 保持活动和画面 |
| 当前持续活动 | 有效双击 | 可以结束活动；睡眠可叫醒 |
| 当前持续活动 | 用户发送聊天消息 | 用户优先，原活动可被取消 |
| 睡着时 | 普通自主搭话时间到 | 不请求主动搭话 |
| 开启自主 AI | 自动音乐检测 | 一般只成为环境线索，不强制切换当前动画 |
| 当前有一条模型请求 | 新普通决策到期 | 不堆积并发请求 |

拖拽、抛掷和右键菜单的额外细节见[交互规则](INTERACTIONS.md)。

## 6. 请求失败和费用

自主决策单次请求将 Provider 的超时上限收紧到 **35 秒**，输出预算上限 **720 tokens**（实际请求还取决于服务商兼容情况）。返回无效格式、接口失败或动画不可用时通常保留现有画面/等待后续判断；错误种类会写入状态面板，不写入原始密钥和完整响应。

普通决策、阶段更新、主动搭话、用户点击回复、正常聊天**可能各自消耗 API 调用**。40 秒间隔并不意味着每天始终发出 2160 次请求：持续活动会跳过普通周期，但阶段更新和主动搭话仍可能独立产生请求。查看 [状态与诊断](DIAGNOSTICS-AND-DATA.md)。

## 7. 已知边界

- 不是通用桌面 Agent；只能使用被验证的本地动作与气泡。
- 早期开发记录 `PR-REPORT-AI-AUTONOMY-2026-10-20.md` 中的简单单步策略和较低超时值已不是当前全部规则。
- 默认夜间在线睡眠**尚未变成连续 6～9 小时**；它仍使用原本的短时 `nap` 活动，离线睡眠另计。
- 行为策略在 Windows 桌面实际效果仍需实机验证；本文件基于源码和测试，不应当替代实际运行诊断。
