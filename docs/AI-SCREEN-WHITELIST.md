# AI 自主识屏白名单（2026-10-21）

## 目标

- 原版独立「主动识屏」后台观察器、右键菜单和设置入口退役。旧配置 `proactive_screen` 仍可保留用于向后兼容，但**不再启动其后台定时器，也不会发起旧版识屏请求**。
- 用户主动点击「看看屏幕」、截图翻译、截图问答等**手动触发的识屏仍可使用**，不受此白名单限制。
- **AI 自主决策的视觉能力**仍需要明确打开「允许自主识屏」，且白名单命中前台程序才截图；没有匹配时按原样执行纯文字决策，不额外调用视觉接口。

## 设置方法

桌宠设置 → AI 与对话 → AI 自主行为 → **允许自主识屏**及**自主识屏程序白名单**。

程序文件名一行一个，例如：

```text
Code.exe
chrome.exe
notepad.exe
```

白名单保存后会被统一变为小写并去重，只接受明确的 Windows `.exe` 基础文件名，**不支持** `*` 通配符、程序路径或网页域名。

> Chrome、Edge 等浏览器白名单允许其任意活动窗口；不能按浏览器标签页精细授权。不要将可能显示密码、支付、客户数据的程序加入白名单。

## 运行规则

| 场景 | AI 自主决策行为 |
|---|---|
| 识屏开关关闭 | 纯文字决策，不截图 |
| 已打开识屏开关，但名单为空 | 纯文字决策，不截图 |
| 前台为白名单程序 | 只尝试截图该前台窗口的矩形区域作为本次决策的图像上下文 |
| 前台程序不在白名单 | 纯文字决策，不截图 |
| 无法获得进程名、窗口尺寸异常 | 纯文字决策，不截图 |
| 截图中切换前台窗口 | 丢弃刚截的图，不上传 |
| AI 正在持续睡眠/其它持续活动 | 继续遵守原有活动锁，不因为识屏设置打断 |
| 手动「看看屏幕」 | 仍按用户手动调用逻辑执行，不使用自主白名单 |

**隐私限制**：Windows 窗口区域抓取是一种屏幕像素捕获。即使只选择了白名单窗口的矩形，如果另一个悬浮窗口叠在该矩形上，该内容仍可能随截图可见；本功能**不保证窗口内容的硬件级隔离**。需要最严格的屏幕隐私时，请关闭「允许自主识屏」。截图仅在内存里编码为 JPEG，发起请求时交给选用的视觉模型；不写入生命状态、聊天历史或独立的截图缓存。

## 实现点

- `pet/autonomy_vision.py`：严格进程名白名单与前台窗口矩形截图/切换复核。
- `pet/autonomy.py`：自主决策唯一视觉入口；空名单禁止抓屏，原版视觉转交禁用。
- `pet/chat/models.py`、`pet/chat/ai_settings_page.py`、`pet/modern_settings_dialog.py`：持久化与 UI。
- `pet/proactive.py`、`pet/window_optional_services.py`、`pet/context_menus/registry.py`：旧独立识屏停用及入口移除。
- `tests/test_autonomy_screen_whitelist.py`：隐私边界与配置往返测试。

本补丁基于 2026-10-21 用户上传的 `dafeiyu-ai-windows-conda-test.zip` 源码，叠加睡眠、番茄钟、精力困意及显式 API 三协议相关补丁，并保留此前 `modern_settings_dialog.py` 协议显示修复。将补丁内 `pet/` 文件覆盖到正在运行的项目中即可，无需重新安装原版，也无需清除 API Key。
