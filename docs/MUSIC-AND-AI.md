# 音乐、歌词与 AI 自主活动的关系

> 对照：`pet/window_alerts.py`、`pet/music_detect.py`、`pet/now_playing.py`、`pet/music_lyric.py`、`pet/music_lyric_controller.py`、`pet/settings_music.py`。

## 1. 听到音乐不等于强制换唱歌动画

| 情形 | 当前代码行为 |
| --- | --- |
| 自动唱歌开启、**AI 自主行为关闭** | 原版音乐检测可触发唱歌动画，静音确认有宽限期，避免换歌或间奏时立刻停止 |
| 自动唱歌开启、**AI 自主行为开启** | 音乐播放状态用于 AI 的环境观察；每秒音乐轮询**不强制打断**工作、睡眠或其他 AI 持续活动 |
| 播放纯音乐 / 没有可唱歌词 | 不应因为纯音乐就强制播放唱歌词的动画 |
| 音乐结束或切歌暂时静音 | 检测带宽限期，避免把短暂静音误判成正在做的事情结束 |

小鲸鱼在工作时可以继续工作，同时知道“主人正在听音乐”。AI 若选择 `music` 活动，则仍应从现有音乐动画中选择，而不是未经用户同意操作真实播放器。

## 2. 歌词如何获取

| 阶段 | 说明 |
| --- | --- |
| 获取当前曲目 | Windows 使用系统媒体会话（SMTC）的歌名、歌手、播放状态等；Spotify 等能上报媒体信息的播放器可以参与 |
| 浏览器网页版 | 由“浏览器媒体会话参与歌词”开关决定是否纳入；网页标题会按规则做适当清理 |
| 搜索歌词 | 缓存优先；网络请求可访问**QQ 音乐、LRCLIB、网易云**等歌词源，并对曲名/歌手做匹配 |
| 结果缓存 | 数据目录的 `lyrics_cache/`，保存歌词文本，不下载或缓存歌曲音频 |
| 歌词缺失或纯音乐 | 按歌曲匹配结果降级，不因此反复强迫动画切换 |

**Spotify 可以提供“正在播什么”的媒体信息，但歌词不是直接读取 Spotify 的歌词数据库。** 相关歌词可能来自 LRCLIB 或其他公共歌词源，是否能查到取决于曲目与匹配结果；不应承诺所有歌曲都能自动显示歌词。

右键菜单里的“打开播放器”配置路径**只负责启动播放器**，不决定歌词的获取源。歌词对齐、浏览器参与、foobar2000 等有独立配置，请看项目音乐设置页。

## 3. 数据与 API 边界

歌词功能访问公共歌词接口，和 AI 自主决策使用的 Chat Completions API **不是同一个请求**。是否启用音乐关联不会自动授权桌面截图；是否开启 AI 自主行为也不意味着歌词功能一定已打开。

排查时可先确认 Windows 系统媒体会话是否确实出现了目标曲目，再看歌词是否缓存命中、是否纯音乐、歌词来源网络是否可用；不要只调整“播放器启动路径”。
