# 大肥鱼 /agent 聊天上下文摘要优化（v6）

## 解决的问题

旧摘要把过期信息、未验证的工具状态和当前任务混在一起，导致 OpenClaw 可能执行旧目标、重复询问，或把模型猜测当作已完成操作。

## 新流程

1. 仅当用户明确输入 `/agent ...` 时启动。
2. 从当前会话最近最多 20 条 user/assistant 纯文本消息中选择历史，单条和总长度都有上限；当前 `/agent` 指令不进入历史摘要。
3. 先对常见 API Key / Token 格式脱敏，再由大肥鱼当前聊天 Provider 单独发起一次摘要请求。摘要请求关闭联网搜索、使用低成本生成参数，不修改正常聊天设置。
4. 摘要提示词要求区分用户明确目标、工具已确认结果、助手推测和过期信息；用户最新纠正优先，旧摘要不作为原始事实。
5. 发给 OpenClaw 的内容是“本次任务原文 + 短摘要 + 执行边界”，不发送完整聊天记录、附件、截图或思考过程。
6. 本次 `/agent` 任务始终放在最高优先级。摘要不能覆盖任务、扩展任务范围或构成额外授权。
7. 摘要 API 失败时不阻断任务，改用带有“未做事实核验”标记的近期对话摘录；用户也可以在 AI 设置里关闭“为 Agent 整理聊天背景”，关闭后只发送任务原文。

## 设置位置

设置 → AI 与对话 → 电脑 Agent（OpenClaw，默认关闭）→ **为 Agent 整理聊天背景**。

## 成本与隐私

开启后，每次明确的 `/agent` 请求会额外调用一次大肥鱼当前聊天模型来压缩最近对话，因此会增加一次模型请求与费用。最多取 20 条文字，限制总字符数，并过滤历史摘要块、脱敏常见密钥格式。摘要请求发送给大肥鱼当前配置的模型服务商；短摘要才会转发给 OpenClaw。关闭开关可完全跳过摘要和历史上下文。
