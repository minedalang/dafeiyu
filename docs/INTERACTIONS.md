# 点击、双击、拖动和右键菜单：优先级

> 对照：`pet/autonomy.py`、`pet/app.py`、`pet/window.py`（传统窗口）、`pet/sprite_behavior.py`（Overlay）、`pet/context_menu_dismiss.py`。

## 1. 用户操作结果表

| 操作 | AI 持续活动进行中 | 没有 AI 持续活动 |
| --- | --- | --- |
| 单击小鲸鱼 | **不打断、不切点击动画、不额外发 AI 点击回复** | 保留原本点击反馈；开启自主行为时可能发一次 AI 点击回复 |
| 快速双击小鲸鱼 | 结束活动；若在睡觉则叫醒，播放点击反馈 | 仍按普通点击交互处理（非特定“叫醒”场景） |
| 温和拖动睡着的小鲸鱼 | 改变位置，**保持睡眠中段动画**；松手也不应闪回待机 | 不适用；普通拖动按原逻辑 |
| 拖动正在进行其他活动的小鲸鱼 | 用户位置控制优先；并非所有动画都保证继续 | 普通悬空 / 拖拽反馈 |
| 高速甩出 | 抛掷物理可接管画面、取消当前活动 | 原有抛掷物理反馈 |
| AI 对话窗口输入消息 | 可能主动取消旧活动并请求适配动作 | 正常聊天、按设置选择动作 |
| 右键菜单 | 只显示操作菜单，不等同于叫醒 | 正常右键菜单 |
| 菜单打开后在外部单击 | Windows 下应一次关闭菜单 | 相同 |

## 2. 双击判定不是 API 限频

程序将同一位置附近、间隔不超过 **0.55 秒**（两次位置相差不超过约 **36 px**）的两次点击认作持续活动的有效打断。

同时还有一条约 **12 秒的点击 AI 回复限频**，它仅用于避免连点刷请求；**不能把 12 秒误当成双击判定时间**。被保护的第一次单击不会偷偷播放点击动画或唤醒持续睡眠。

## 3. 为什么旧版拖动时会闪一下？

传统窗口和 Overlay 原先在鼠标拖拽超过阈值时，会自动切到悬空动作；松手再切回待机。AI 睡眠的循环控制随后才重新恢复睡眠，造成你看到的“拖一下先变动画，再睡回去”。

最近的修复把**睡眠中拖动位置**与**切换动画**分开：

- 传统窗口中：若当前仍持有自主睡眠/持续循环动画，温和拖动和松手不再强制换到悬空或待机。
- Overlay 中：处于本地受保护 `STATE_HELD` 状态时，拖拽开始/松手不触发普通拖拽动画切换。
- 高速甩出属于不同物理接管路径，不承诺继续原地睡姿。

## 4. Windows 右键菜单为什么需要特殊处理？

桌宠窗口为了不抢其他应用的键盘焦点，会使用 Windows 非激活窗口行为。这会使 Qt 菜单偶尔无法在**第一次点击菜单外**时收到失焦通知。

`pet/context_menu_dismiss.py` 在**菜单显示期间**用一个约 16 毫秒的轻量检查确认是否发生了新的左键按下，且点击点不在菜单或可见子菜单内部；满足条件时主动关闭菜单。这个实现**不是常驻全局鼠标钩子**，不记录键盘/鼠标轨迹，也不主动消费其他软件的点击事件。

Windows GUI 行为需在用户电脑上验收；文档说明代码策略，不把跨桌面焦点问题写成在所有系统上都已验证。

## 5. 建议验收用例

| 测试场景 | 预期 |
| --- | --- |
| 睡眠动画循环时单击 | 持续睡眠，睡眠截止时间保持不变 |
| 睡眠时在 0.55 秒内双击 | 结束睡眠并进行唤醒反馈 |
| 睡眠时缓慢拖到桌面另一侧 | 保持睡姿，松手后无悬空/待机闪变 |
| 睡眠时故意高速甩出 | 允许抛掷物理接管 |
| 工作活动播放中等过 40 秒 | 不因普通自主决策强制换活动 |
| 右键打开菜单，直接点击桌面或其他软件 | 第一次外部单击就关闭菜单；菜单项仍能正常选中 |
