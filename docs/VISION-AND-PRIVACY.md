# 识屏、API 数据流与隐私边界

> 对照：`pet/autonomy.py`、`pet/app.py`、`pet/vision.py`、`pet/proactive.py`、`pet/chat/models.py`、`pet/autonomy_monitor.py`。

## 1. 自主识屏与“原版主动识屏”是两个开关

| AI 自主行为 | 允许自主识屏 | 原版主动识屏 | 当前图片决策路径 |
| --- | --- | --- | --- |
| 关闭 | 不论 | 关闭 | 不会由自主服务上传截图 |
| 关闭 | 不论 | 开启 | 原版主动识屏独立处理（仍受自身授权与筛选条件约束） |
| 开启 | 关闭 | 关闭 | 纯文本观察：时间、位置、生命状态、活动及近期对话 |
| 开启 | 开启 | 关闭 | 自主决策可在每次需要时自行截取桌面，发送给视觉模型 |
| 开启 | 关闭 | 开启 | 原版主动识屏捕捉**符合白名单等条件的前台窗口**并转交统一自主服务 |
| 开启 | 开启 | 开启 | 优先共用原版前台窗口白名单截图，避免自主服务对同一次观察再截全屏 |

这里的“原版主动识屏”还有自己的筛选条件、频率限制以及窗口停留逻辑；“开启”并不等于时时读取所有软件内容。**图片经用户授权后会发送到所配置的第三方模型 API**，不仅是保存在内存里。请在需要时才开启视觉相关开关，不应把视觉功能视作普通本地传感器。

## 2. 模型请求携带的数据

| 数据 | 不启用识屏 | 启用相应视觉授权后 |
| --- | --- | --- |
| 本地时间、生命状态、动画名单、行为历史 | 可发送 | 可发送 |
| 近期对话文本（限量裁剪） | 可发送 | 可发送 |
| 桌宠/鼠标状态和界面观测 | 可发送 | 可发送 |
| 桌面或前台窗口图像 | **不发送** | 可附加为 JPEG 图片请求内容 |
| API 密钥 | 用于 HTTP 鉴权 | 同样用于 HTTP 鉴权 |

截图只在内存中作为模型请求输入，统一自主系统不会把截图写进 `whale-life-state.json`、状态监控 JSON 或聊天历史。但这**不代表第三方 API 不会接收图片**；服务商侧数据处理以所用网关及模型提供者的隐私条款为准。

## 3. 模型与费用

正常对话、自主决策、阶段更新、独立搭话、点击回应可能是分开的 API 请求。视觉模型不一定与普通文字模型相同，配置中有视觉模型、视觉 API 地址和密钥选项；对应网关需要支持带图片的 OpenAI 兼容聊天接口。

- 开启识屏只应使用你信任的网关；注意截图可能包含账号信息、私人聊天、打开的文档。
- 状态监控**不记录**完整提示词、截图、API Key 或原始模型响应；仅存模型标识、次数、摘要结果、状态和错误类型。
- System Prompt 指导小鲸鱼的语气，但无法替代本地代码中的动作白名单和屏幕授权控制。
- 关闭自主行为后，原版主动识屏与普通聊天仍可能独立使用网络；要完全不调用相关外部服务，请同时关闭对应功能。

## 4. 安全边界与已知限制

模型给自主服务的 `play` 动画必须存在于当前素材集合，动作类型是白名单。自主决策**没有**通过 JSON 动作执行 shell 命令、移动真实鼠标、键盘输入或写文件的通用执行工具。

独立识屏相关能力来自原桌宠项目；这里仅说明与自主服务的**统一调用关系**，不替代原版识屏模块各自详细的白名单、静默时间和屏蔽窗口设置。对于敏感应用，最保守的选项是将两种识屏开关都关闭。
